# 数据分层建模工作台

离线版数仓分层建模工具，覆盖贴源层、明细层、汇总层、应用层的表结构设计、分区策略配置、质量规则编排与血缘关系管理，数据持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-layer-studio:entries` 与 `data-layer-studio:ods-runtime` 两项，
  或调用 `resetModule(模块)`（重置贴源层会连带清空代次 / 回执 / 令牌）。

## 贴源层链路的判定规则

贴源层不是「点一下启用就变成已启用」，而是沿着 **贴源条目 → 模块动作表 → 数据源连接 → 数据同步 → 概览**
一条链核对。判定逻辑只有一份，在 `local-service.ts` 的 `evaluateOdsEligibility` / `buildOdsHealth`，
列表、详情面板和运营概览都读它，不再各自读 `pending` / `abnormal` 布尔值。

- **启用资格 = 源端握手 + 字段映射版本 + 校验回执**，三者缺一不可：
  - 源端握手：贴源表的「源端连接」必须在数据源管理里是「已连通」。
  - 字段映射版本：运行态固化的映射版本、贴源表登记版本、映射登记表三者一致。
  - 校验回执：当前执行代次、当前映射版本、结果「通过」。
- 「启用同步」只能从「待校验」发起，且资格三项全部成立才发放令牌、改成「已启用」。
- **执行代次**：停用同步即结束当前代次并另开下一代（代次 +1）。代次 / 映射不匹配的回执一律**归档**，
  不写入有效回执，也**不覆盖新代次水位**；只有当前代次的「通过」回执能推进水位。
- **启用令牌**：同一张贴源表、同一代次只发一张。两个标签页争抢时，先写入者持有令牌，
  败者拿到 `TOKEN_HELD`，消息与详情里的动作记录都带令牌号、持有者、代次，便于核对。
- **数据同步**：「启动同步」要求联动的贴源表处于有效「已启用」、源端连接已连通、贴源表与链路的回放批次一致；
  任一不成立就阻断。已置为「运行中」但前置失效的链路，列表与概览会显示「运行中（前置失效）」。
- **回看**：以贴源表为主对象核对回放批次（详情面板的「核对回放批次」），结果写入回放核对记录与动作日志。
- **概览**：贴源表资格失效、同步链路前置失效、质量规则上游失效都会出现在「阻断与告警」里，
  不再继续给出正常信号。
